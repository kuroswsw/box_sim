# box_sim — 移動式ゴミ箱(自動捕球ロボット) 設計シミュレータ

実機製作前に機構寸法と制御則をデジタル上で探索・比較するためのツール。
実投擲の完全な代替ではなく、**実投擲を「パラメータ同定用の数十投」に削減する**ことが目標。

## 技術選定の理由

### 物理: 自前実装（PyBulletではない）

支配的な物理は**質点の弾道＋抗力**であり、剛体接触は「捕球面を横切ったか」の1判定に縮約できる。この用途で PyBullet を使う積極的理由がなく、以下の点で自前実装が明確に優る。

1. **バッチベクトル化**。設計探索は 6×6格子×1000試行 = 36,000投を1回のスライダ操作で回す。自前実装なら NumPy で N本の軌道を同時積分でき、実測で 1000試行が約0.4秒。PyBullet は1ステップ1ワールドが基本で、これを2桁遅くする。ビューCの応答性がツールの主目的そのものなので、ここは譲れない。
2. **同定と予測でモデルを共有できる**。キャリブレーション（`sim/calibration.py`）は最小二乗の残差評価でシミュレータ本体と同じ `simulate_batch` を呼ぶ。EKF の運動モデルも同じ式。物理エンジンを挟むとモデルが二重管理になり、「同定したCdAが予測に効いているか」が保証できなくなる。
3. **必要な物理が少ない**。剛体同士の衝突も関節も摩擦接触も要らない。要るのは抗力とバウンド係数だけで、PyBullet の機能の大半が無駄。

破綻する条件: 受け口の膜と物体の相互作用（跳ね返り・巻き込み）を詳細に見たくなったら自前実装では足りない。その段階で PyBullet か MuJoCo を「膜の設計検証専用」に別途導入するのが正しく、本体シミュレータに混ぜるべきではない。

### GUI: Plotly Dash（PyQt / Three.js ではない）

- 4ビューのうち3つ（B/C/D）は本質的にグラフであり、Plotly の完成度がそのまま使える。ヒートマップ・共分散楕円・散布図を自分で描く工数がゼロ。
- Dash のコールバック機構がパラメータ→再計算→再描画の配線とそのまま一致する。PyQt だと同じことをシグナル/スロットで手書きすることになる。
- Python プロセス内で完結するので、シミュレータのオブジェクトをそのまま Figure に渡せる。Three.js だと軌道データを JSON でシリアライズして渡す層が必要になり、その層が設計探索には何も貢献しない。
- ビューAの3D描画は Plotly の Scatter3d で足りる（軌道・機体・受け口リング・共分散楕円）。Three.js 相当の描画品質は本ツールの目的に不要。

破綻する条件: 受け口の展開機構をリブ・膜の形状レベルで見たくなったら Scatter3d では表現力が足りない。その場合はビューAだけ Three.js に差し替える（他の3ビューは Dash のまま）。

## 実装段階と検証結果

指示どおり最小構成から積み上げた。各段階でスモークテストが通っている。

**Stage 1**（剛体1種＋物理のみ）— `scripts/smoke_stage1.py`
真空理論解との比較で積分器を検証。PET(満)の抗力による水平方向の減少は 2.3cm（滞空0.76秒）で、質量0.525kg・CdA 0.006 の想定に対して妥当。ティッシュは同一初期条件で平均1.7m手前に落ち、着地点の散らばりが x方向14cm・y方向25cm 出る。

**Stage 2**（機体＋センサ＋EKF＋制御ループ）— `scripts/smoke_stage2.py`
単発（ばらつきなし）で予測誤差が初回100cm→最終1.0cmに収束。200試行のバッチで PET(満) 捕球率89%、ティッシュ0%。感度の符号が正しいことを確認: 受け口12cm→81% / 35cm→96%、レイテンシ20ms→95% / 250ms→66%。

**Stage 3**（キャリブレーション＋設計探索）— `scripts/smoke_stage3.py`
真値を既知にした擬似実測データで、CdA 0.00896（真値0.00900）、反発係数0.585（真値0.585）を復元。残差RMSは同定前7.34cm→同定後1.40cm。1000試行×格子点のヒートマップが実用速度で回る。

## モデルの割り切りと、どこで破綻するか

### 物体モデル（3種を別扱い）

**ペットボトル（空/半分/満）** — 剛体。慣性テンソルを中身の量で変える（円筒近似）。抗力は Cd·A 一定近似。

破綻箇所: タンブリングすると実際の投影面積は周期変動し、抗力が ±30% 程度揺れる。滞空0.5〜0.8秒では着地点に数cmの系統誤差として出る。キャリブレーションで「平均的なCdA」に吸収する方針だが、回転の激しい投げ方（弾く）では吸収しきれない。また半分入りのスロッシング（液体の揺動）は完全に無視しており、これは中身が半分のときだけ効く誤差なので、`pet_half` の予測は他の2つより信頼度が低いと考えるべき。

**一般ゴミ（缶・紙くず）** — 同じく質点＋Cd·A一定近似。紙くずには軽度のOU外乱を入れている。

破綻箇所: 缶は形状が単純なのでモデルは素直だが、紙くずは丸め方で CdA が個体ごとに2倍変わる。カタログ値は「代表的な1個」でしかない。

**ティッシュ** — 剛体近似が破綻するので、等価球（半径4cm、Cd=2.0）＋大きなCdA＋Ornstein-Uhlenbeck過程による外乱で近似。

これは意図的な割り切りで、**個々の軌道を当てることは目的ではない**。目的は「決定論的には予測できない」という性質そのものを再現し、どの物体が予測可能でどれが不可能かを判別すること。ビューBで見ると、ティッシュと紙くずだけEKFの共分散が収束しない。これがモデルの意図した出力であり、実機で「ティッシュは諦める / 別の戦略を取る」という設計判断の根拠になる。

破綻箇所: OU過程のパラメータ（σ=3.0 m/s²、τ=0.15s）は物理から導いたものではなく、「予測不能に見える」ように選んだ値。実測ティッシュの散布と定量的に一致する保証はない。σ を実測から合わせ込むこと自体は可能だが、それをやっても「決定論的に当てられない」という結論は変わらないので、優先度は低い。

### 機体モデル

3輪オムニ（120°配置）。加速度指令 → 車輪力配分 → 車輪ごとの電流飽和 → 1次遅れ（τ=30ms）→ 摩擦限界チェック → スリップ時は動摩擦に低下 → 積分＋v_maxクランプ。

破綻箇所:
- **ヨー回転を無視**している。オムニで並進と独立に制御できる前提だが、実機ではヨー外乱トルクで配分が数%食われる。
- **FOC電気系と機械系を1次遅れ1本に縮約**。FOC帯域(kHz)は機械系(数十Hz)よりずっと速いので実用上は機械系時定数だけが見える、という近似。電流制御がうまく効かない場合（低速域のセンサレス等）はこの近似が崩れる。
- **スリップは等方クーロン摩擦**。オムニホイールの樽ローラは進行方向で摩擦係数が実測±20%変わるが無視している。μをスライダで振って感度を見る使い方を想定。
- **転倒を動力学として解いていない**。「重心高さ ≤ トレッド半分」の設計制約と、準静的限界 a_tip = g·R/h の表示のみ。急峻な加速度反転時の動的転倒は本シミュでは検出できない。ビューCで a_max がこの限界を超えると警告を出してクリップする。

### センサモデル

カメラのフレームレート、露光遅延、処理遅延を**合計レイテンシ**としてパラメータ化。指示どおり最大のボトルネックとして可変にしてある（ビューCの軸に選べる）。

破綻箇所: 3D位置が等方ガウス雑音で直接得られる前提（ステレオ or 既知サイズの単眼）。実際は奥行き誤差が視差に反比例するので距離依存かつ異方性。雑音stdを振って許容範囲を見る使い方を想定。また検出率100%（視野内にある間）としており、モーションブラーによる検出落ちは扱わない。fpsを下げることで擬似的な評価は可能。

### 着地点予測の共分散

交差時刻の不確かさ var(t) ≈ P_zz/vz² を水平共分散に v_xy·v_xyᵀ·var(t) として足している。交差時刻と水平位置の相互相関 P_xz を無視しているため、共分散楕円は数%過小評価。展開判断の閾値付近で効くが、`deploy_margin` のヒステリシスで実用上は吸収される。

### 時間最適軌道

「到着時刻指定の加速度則」 a = 2((r_target - r) - v·t_go)/t_go² を a_max でクリップする実用近似。t_go が足りない領域では自動的に全力加速になる。真の時間最適（バンバン制御）との差は数%程度。0.3秒で11cmという支配的制約の下では、この差は受け口径の数mmに相当し、設計判断を変えるレベルではない。

## キャリブレーション手順

「キャリブレーション」タブで、実測した投擲軌跡CSV（列: `t,x,y,z`）を読み込む。

同定するのは Cd·A と反発係数、および初期状態（位置・速度）。初期状態も未知数に含めるのは、最初の数点から求めると計測雑音で偏るため。

出力:
- CdA と反発係数の推定値と**95%信頼区間**
- **同定前後の残差**（時系列グラフ＋RMS）
- 残差RMSの2倍を「シミュレータの信頼区間」として明示

読み方: 同定後の残差RMSがカメラ計測誤差（数mm〜2cm）まで落ちていれば、Cd·A一定モデルはこのデータに対して十分。有意に大きければ「このモデルではこれ以上詰められない」というシグナルで、タンブリングの影響が無視できない領域に入っている。

反発係数の信頼区間が広い場合は、データにバウンドが含まれていない（＝反発係数に感度がない）ことを警告する。

**「サンプルCSVで試す」ボタン**で、真値を既知にした擬似データで動作を確認できる。真値 CdA=カタログ値×1.2、e=カタログ値×1.3 で生成したデータから、両方を95%信頼区間内で復元することを確認済み。

ティッシュには適用不可（残差が同定誤差ではなく外乱なので、最小二乗の前提が成立しない）。

## 学習を使う箇所（ここに限定）

指示どおり、軌道予測にも制御にもニューラルネットは使わない。予測は物理モデル＋EKFのみ。

**投擲の事前予測** (`learning/train_lstm.py`): MediaPipe Pose の骨格系列から、リリース前に初速ベクトルを回帰する小型LSTM（2層、hidden=64）。**学習データはシミュレータではなく実測**。シミュレータ上では「事前予測が何ms早いと捕球率が何%上がるか」の感度解析にのみ使う。

シミュレータ側では、LSTM の効果を2つのパラメータに縮約している:
- `lead_time`: リリース何秒前から動き出せるか（ビューCのスライダ）
- `lstm_err_std`: 事前予測の着地点誤差 [m]（学習結果の val 誤差から換算）

学習を回すと val 誤差から `lstm_err_std` の目安が出力されるので、それをシミュレータに入れて感度を見る。この分離により、LSTMが未完成でも「どれだけの精度・リード時間があれば投資に見合うか」を先に決められる。

実際に測ると効果は大きい。センサ遅延150ms・受け口15cmの条件（500試行）で、リード時間 0ms→73.0%、50ms→94.2%、100ms→96.4%、200ms→97.4%。**最初の50msが圧倒的に効いて、それ以降は飽和する**。つまりLSTMは「わずかでもリリース前に動き出せること」に価値があり、長いリード時間を狙って精度を落とすのは割に合わない。この結論はLSTMを実装する前に得られている。

**物体分類** (`learning/classify.py`): YOLOv8n / MobileNetV3。質量・Cdの事前分布を選ぶためだけに使う。分類結果はEKFのβ初期値と初期共分散に入るだけで、軌道予測そのものは物理モデルが行う。クラス確率を渡すと混合分布として事前分布を広げるので、誤分類の影響も評価できる。

学習は PyTorch、推論は ONNX Runtime。`--demo` フラグで、実測データがない段階でもビューDの配線を確認できる（DEMO表示付き。学習性能の評価には使えない）。

## GUI の4ビュー

**A: 3Dシーン** — 軌道、機体、受け口の展開（リブ4本）、予測着地点の2σ共分散楕円をリアルタイム描画。再生・一時停止・スロー再生（等速 / 1/4 / 1/10）。スライダで任意時刻へシーク。

**B: 予測誤差** — 着地点予測誤差とEKF共分散の収束を時間軸で表示、物体種別ごとに色分け。同一の投擲条件で全6物体を1投ずつ飛ばして比較する。ティッシュと紙くずだけ共分散が収束しないことが確認できる。

**C: 設計探索** ★ — 本ツールの主目的。受け口径・展開時間・最大加速度・センサ遅延の4軸から2軸を選び、モンテカルロ1000試行の捕球率をヒートマップ表示。残り2軸はスライダで固定。LSTMリード時間もスライダで振れる。

全格子点で**共通乱数**（同一シード）を使っているので、格子間の差はモンテカルロ雑音ではなく設計の差を表す。タイトルにモンテカルロ誤差の大きさ（1000試行なら ±3.1pt）を表示するので、有意な差かどうか判断できる。

**D: 学習** — 事前予測LSTMの損失曲線と、予測初速ベクトル vs 実測初速ベクトルの散布図（vx/vy/vz別）。

## 既定の前提（変更していない）

- 機体: 3輪オムニ、小型BLDC＋遊星5〜10:1、FOC電流制御
- 支配的制約は加速度。落下時間0.55秒のうち実効的に動けるのは約0.3秒、走行距離11cm程度。したがって駆動系の高速化ではなく受け口の拡大が性能の主戦場
- 受け口: 展開式。バネ蓄勢＋ソレノイドでシアー解放、サーボウインチで再装填。リブ4本対称。膜はたるませて跳ね返りを防ぐ。展開トリガは「予測着地点が基部外に出たときのみ」
- 重心高さ ≤ トレッド半分（転倒条件）
- 軌道予測は物理モデル＋拡張カルマンフィルタ。ニューラルネットは軌道予測にも制御にも使わない

デフォルト値の `a_max = 2.4 m/s²` は「0.3秒で11cm」から逆算した値（2·0.11/0.3² ≈ 2.4）。

「制約は加速度であって最高速度ではない」という前提はシミュレータ上でも確認できる。500試行で v_max を振ると 0.8 m/s で82.4%、1.6 m/s で88.2%、3.0 m/s でも88.2% と、1.6 m/s 以上では完全に頭打ちになる（0.3秒の加速で到達できるのは0.72m/s なので当然）。逆に 0.8 m/s まで下げると効き始めるので、**最高速度は「1.6 m/s あれば十分、それ以上は無駄」**という設計指針が読める。駆動系の高速化ではなく受け口の拡大が主戦場、という前提と整合している。
